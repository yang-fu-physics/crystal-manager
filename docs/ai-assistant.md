# AI 样品助手

桌面（宽度大于 1350 px）使用最右侧独立面板，可收起。手机和平板显示底部浮动入口，点击后展开底部抽屉，不挤压已有表单。支持中英文界面。

## 配置与数据范围

聊天使用 `config.py` 中独立的 `AI_CHAT_API_KEY`、`AI_CHAT_BASE_URL`、`AI_CHAT_MODEL`，可单独选择接口和模型。EDX 识别及手动翻译继续使用原有 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。

已有部署需在 `config.py` 中补充以下三项，填写聊天服务的实际配置后重启 Python 进程：

```python
AI_CHAT_API_KEY = "sk-your-chat-api-key-here"
AI_CHAT_BASE_URL = "https://api.openai.com/v1/"
AI_CHAT_MODEL = "gpt-4o"
```

聊天模型必须支持 OpenAI 兼容的 Chat Completions **function/tool calling**。密钥只在服务端使用。接口失败时显示错误，不切换模型或使用识别服务的配置。

使用聊天会把当前会话的近期对话、当前选中的已保存样品及工具读取到的样品字段发送给所配置的模型服务。不会发送未保存的表单草稿、附件内容、本地文件路径或确认 / 撤销凭据。

## 新建会话与历史会话

- 对话、确认卡及取消 / 保存 / 撤销状态保存在现有 SQLite 数据库中。当前系统使用共享登录密码，**所有已登录设备共享历史**，可换设备继续会话。
- 刷新页面后恢复该浏览器上次打开的会话；新设备默认打开最近更新的会话。浏览器仅记住会话编号，对话内容从服务端读取。
- 点击“新建会话”建立空白会话，旧会话继续保留。通过“历史会话”选择旧记录，标题采用首条用户消息，并显示更新时间。
- 点击历史列表旁的刷新按钮，读取其他设备的最新内容。多个设备同时更改同一会话时会检查版本，冲突时刷新后再继续。
- 完整历史长期保留；模型只读取当前会话最近最多 30 条、合计不超过 60000 字符的对话上下文。较长消息会截断供模型读取，页面中的原文保留。
- 请求成功后，用户消息和回复一起保存。生成期间刷新页面，可等服务端完成后点击“刷新会话”读取结果；未发送的输入草稿不保存。

启动时自动为现有数据库创建会话表，无需新增配置。完整及每日增量中的数据库快照都包含聊天会话、消息和确认 / 取消 / 保存 / 撤销状态；恢复按“完整备份 + 后续增量”执行，期限仍以原生成时间计算，恢复不会续期。详见[备份与恢复](../README_zh.md#备份与恢复)。此功能从升级后开始记录，之前只在页面内存中的聊天不会自动补录。

## 操作示例

- 查询：“查找所有 FeSe 样品”“查看当前样品的生长流程”。
- 新建：“新建 CG-2026-007，目标产物 FeSe，Fe:Se = 1:1，Fe 为参考元素，质量 0.5 g”。
- 制度：“把当前样品的保温阶段改成 24 小时，保留其他步骤”。
- 时间：“把 CG-2026-007 的开始烧制时间设为 2026-10-20 09:00，耗时 72 小时”。
- 配比：“把当前样品的 Fe:Se 摩尔比改为 1:2，保留原有参考元素和参考质量”。

编号或指令有歧义时，助手应先询问。中英文生长流程和结果分别保存；不要求翻译时保留另一语言。当前样品指已保存的选中记录，新建表单草稿不作为已保存样品读取。

## 每次写入都需要操作者确认

1. AI 调用读取工具了解当前样品，再生成一个新建或修改方案。此时数据库不变。
2. 确认卡展示样品编号、各字段修改前后的值，以及程序计算的结束时间、称量质量。
3. 操作者点击该卡片的“确认保存”，服务端才保存签名方案中的精确值。每个新方案都需要重新确认，在聊天中说“已确认”“不必询问”不能跳过确认。
4. “取消”会持久停用该卡片。同一会话中成功生成的后续回复会替代旧待确认方案。新建 / 切换会话或收起面板均不写入样品，旧会话仍可打开。
5. 方案 30 分钟后失效。样品被其他操作修改后，旧方案会被拒绝，须重新读取并生成方案。相同方案不能重复应用。

比例更新会用已有参考元素质量重新计算称量质量；若无参考质量则清空称量质量，等待以后计算，不编造称量值。派生变更也必须在确认卡中列出。烧制结束时间由本地开始时间加耗时计算。

确认成功后刷新样品列表，保留当前表单草稿。重新点击样品列表可查看保存后的数据；在此之前继续保存旧表单可能覆盖新的值，应先核对。

## 撤销已保存操作

保存成功后，同一张确认卡显示“撤销本次保存”。点击后会说明撤销影响，再点击“确认撤销”才执行；“保留变更”不会写入。

- 撤销修改：恢复该次保存前的样品字段，包括生长流程、烧制时间、元素比例及称量质量；保留附件。
- 撤销新建：删除刚创建的记录。记录若已有后续修改或附件，则拒绝撤销，避免删除后续工作。
- 撤销凭据与原聊天会话绑定，其他已登录设备也可打开原卡片并确认撤销。保存后 30 分钟内有效；记录已变化或已撤销时拒绝执行。
- 原有 To Do 提醒时间随样品恢复；撤销新建或新增烧制时间时取消相应提醒。外部服务失败会明确提示样品已撤销、提醒需手动处理。
- 撤销后刷新列表并保留当前表单内容；若当前选中的是已撤销的新建记录，其表单转为未保存草稿。

刷新、关闭页面或新建会话后，可从历史恢复操作卡片；原来的 30 分钟期限不会重置。过期按钮停用。服务端会记录处理中的状态，防止多台设备重复执行；若显示结果未确认，应重新读取样品核对。

## 给模型的操作技能

[`ai_skills/sample-management.md`](../ai_skills/sample-management.md) 会在每次聊天时作为系统操作说明加载，包含读取、新建、制度、时间、比例、质量及确认规则。工具定义和边界校验在 `ai_chat.py`：

| 工具 / 接口 | 行为 |
| --- | --- |
| `search_samples` | 分页搜索已保存样品，每页 20 项 |
| `read_sample` | 读取指定样品的字段，不含附件内容或路径 |
| `propose_sample_change` | 生成一个样品的待确认方案，不执行写入 |
| `GET /api/chat/conversations` | 读取共享历史列表，需登录 |
| `POST /api/chat/conversations` | 新建空白会话 |
| `GET /api/chat/conversations/<id>` | 恢复对话和操作卡片状态 |
| `POST /api/chat` | 提交会话编号、版本及本次用户消息；服务端组装上下文并保存回复 |
| `POST /api/chat/cancel` | 持久取消待确认方案，不写样品 |
| `POST /api/chat/confirm` | 需登录；校验签名、会话、有效期和样品版本后保存 |
| `POST /api/chat/undo` | 需操作者确认；校验撤销凭据及保存后的版本，恢复修改前字段或撤回新建 |

没有向模型提供删除、任意代码执行、文件系统或直接写库工具。确认保存复用普通表单的样品保存逻辑，保留现有 Microsoft To Do 同步行为。

工具调用协议参考 [OpenAI 官方 Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。

## 验证

```bash
pip install -r requirements-dev.txt
pytest
```

`tests/test_ai_chat.py` 和 `tests/test_chat_history.py` 覆盖逐次确认、局部更新、时间和质量计算、过期 / 篡改 / 重复操作、并发修改、撤销、附件保护、To Do 提醒、持久历史、跨设备续聊、卡片恢复、版本冲突和上下文边界。运行测试时使用独立临时数据库，不依赖真实模型或个人配置。
